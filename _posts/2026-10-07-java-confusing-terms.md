# 자바 용어 정리 (학습 흐름 순서)

## 1. 리터럴 (Literal)
코드에 직접 적어 넣은 값 그 자체이다. 변수는 값을 담는 그릇이고, 리터럴은 그 안에 담기는 값이다.

```java
int a = 10;          // 10 → 정수 리터럴
String s = "hello";  // "hello" → 문자열 리터럴
boolean b = true;    // true → 논리 리터럴
```

## 2. 참조 자료형 (Reference Type)
값 자체가 아니라 객체가 저장된 메모리 주소(참조)를 담는 타입이다. 기본형(`int`, `double`, `boolean` 등)을 제외한 거의 모든 타입이 해당한다. `String`, 배열, `List`, 직접 만든 클래스(`Car`, `Rabbit`)가 그 예이다.

```java
int x = 5;               // 기본 자료형: 5 자체가 저장된다
Car car = new Car();     // 참조 자료형: 객체의 주소가 저장된다
```

## 3. 클래스 (Class)와 인스턴스 (Instance)
클래스는 객체를 만들기 위한 설계도이고, 인스턴스는 `new`로 클래스를 실제로 만들어낸 실물이다. 붕어빵 틀이 클래스, 틀로 찍어낸 붕어빵이 인스턴스이다. 객체와 인스턴스는 거의 같은 말이며, 어떤 클래스로 만들어졌는지를 강조할 때 인스턴스라고 한다.

```java
Rabbit r1 = new Rabbit();   // 인스턴스 1
Rabbit r2 = new Rabbit();   // 인스턴스 2 (r1과 별개)
```

## 4. 필드 (Field)
클래스 바로 아래에 선언된 변수이며, 객체가 가지는 데이터(속성)이다. 인스턴스가 만들어질 때 각자 복사본을 가지므로 인스턴스 변수라고도 한다.

```java
public class Rabbit {
    String name;                    // 필드 (클래스 바로 아래)

    public void eat(String food) {  // food: 매개변수
        int count = 1;              // count: 지역변수 (메서드 안)
    }
}
```

| 구분 | 위치 |
|---|---|
| 필드 | 클래스 바로 아래 |
| 매개변수 | 메서드 정의의 괄호 안 |
| 지역변수 | 메서드 몸체 안 |

## 5. 메서드 (Method)
클래스 안에 들어 있는, 어떤 동작을 수행하는 코드 묶음이다. 필드가 명사(데이터)라면 메서드는 동사(행동)이다.

```java
public  void  eat  (String food)  { ... }
  ①     ②     ③        ④          ⑤
```

| 번호 | 이름 | 설명 |
|---|---|---|
| ① | 접근제어자 | 어디서 호출할 수 있는지 결정한다 |
| ② | 반환형 | 실행 후 돌려주는 값의 타입이며, 없으면 `void`이다 |
| ③ | 메서드 이름 | 호출할 때 사용한다 |
| ④ | 매개변수 | 받을 값이다 |
| ⑤ | 몸체 | 실제 실행되는 코드이다 |

호출할 때 괄호가 있으면 메서드, 없으면 필드이다. (`arr.length`는 배열의 필드, `str.length()`는 String의 메서드이다.) `static` 메서드는 인스턴스 없이 `클래스명.메서드()`로 호출하며, 인스턴스 필드는 사용할 수 없다.

## 6. 매개변수 (Parameter)와 전달인자 (Argument)
매개변수는 메서드를 정의할 때 괄호 안에 적는, 값을 받기 위한 변수이다. 전달인자는 메서드를 호출할 때 괄호 안에 실제로 넘기는 값이다. 정의하는 곳이 매개변수, 호출하는 곳이 전달인자이다. 택배에 비유하면 전달인자는 보내는 물건이고, 매개변수는 받는 쪽의 빈 상자이다.

```java
void eat(String food) { }     // 정의: food는 매개변수
eat("당근");                   // 호출: "당근"은 전달인자
```

## 7. 시그니처 (Signature)
메서드를 구분하는 식별 정보로, 메서드 이름과 매개변수의 타입, 개수, 순서로 이루어진다. 반환형과 접근제어자는 포함하지 않는다.

```java
public int add(int a, int b)           // 시그니처: add(int, int)
public double add(double a, double b)  // 시그니처: add(double, double) → 다른 메서드
```

- 이름은 같고 시그니처가 다르면 **오버로딩**이다.
- 부모와 시그니처가 같게 다시 정의하면 **오버라이딩**이다.

## 8. 생성자 (Constructor)
`new`로 객체를 만들 때 자동 호출되어 초기 설정을 하는 특수한 메서드이다. 이름이 클래스명과 같고 반환형이 없다. 생성자를 하나라도 직접 작성하면 기본 생성자는 자동 생성되지 않으므로, 빈 상태로도 만들려면 기본 생성자를 직접 작성해야 한다.

```java
public RabbitFarm() {}                  // 기본 생성자
public RabbitFarm(T animal) { ... }     // 매개변수 생성자 (오버로딩)

new RabbitFarm<Rabbit>()                // 기본 생성자 호출
new RabbitFarm<Rabbit>(new Rabbit())    // 매개변수 생성자 호출
```

## 9. this
현재 만들어지고 있거나 실행 중인 객체 자기 자신을 가리키는 참조이다. 매개변수와 필드의 이름이 같을 때 필드를 지정하기 위해 주로 사용한다.

```java
public Rabbit(String name) {
    name = name;         // 매개변수가 자기 자신에게 대입될 뿐, 의미 없음
    this.name = name;    // 올바름: 필드 name ← 매개변수 name
}
```

값의 이동 경로는 다음과 같다.

```
"뭉치" ──(전달)──▶ name(매개변수) ──(this.name = name)──▶ name(필드)
전달인자             매개변수                                필드
```

## 10. 상속 (Inheritance)
부모 클래스의 필드와 메서드를 자식 클래스가 물려받는 것이다. `extends`를 사용하며, 자식 클래스에서 부모를 가리킬 때는 `super`를 쓴다. 자식이 부모의 메서드를 같은 시그니처로 다시 정의하는 것이 오버라이딩이다.

```java
public class CapsCar extends Car {
    @Override
    public void run() { super.run(); }
}
```

## 11. 인터페이스 (Interface)
"이런 메서드를 반드시 구현해야 한다"는 약속(규격)만 정의한 것이다. 구현은 `implements`로 클래스가 한다. 클래스는 상속을 하나만 받을 수 있지만 인터페이스는 여러 개 구현할 수 있다. `List`는 인터페이스이고 `ArrayList`는 그 구현체이다.

```java
interface Drivable { void run(); }
class Car implements Drivable {
    public void run() { ... }
}
```

## 흐름 한눈에 보기

```
리터럴 (값 자체)
  → 참조 자료형 (값 vs 주소)
    → 클래스 / 인스턴스 (설계도 vs 실물)
      → 필드 (객체가 가진 데이터)
        → 메서드 (객체가 하는 동작)
          → 매개변수 / 전달인자 (메서드에 값 주고받기)
            → 시그니처 (메서드 구분 기준 → 오버로딩)
              → 생성자 (객체 생성 시 호출되는 특수 메서드)
                → this (객체 자기 자신)
                  → 상속 (물려받기, 오버라이딩, super)
                    → 인터페이스 (규격 정의, 다형성으로 연결)
```

## 자주 헷갈리는 구분 요약

| 헷갈리는 쌍 | 구분 기준 |
|---|---|
| 매개변수 vs 전달인자 | 정의하는 곳 vs 호출하는 곳 |
| 필드 vs 매개변수 vs 지역변수 | 클래스 바로 아래 vs 괄호 안 vs 메서드 몸체 안 |
| 클래스 vs 인스턴스 | 설계도 vs `new`로 만든 실물 |
| 메서드 vs 생성자 | 반환형 유무, 이름이 클래스명과 같은지 |
| 상속 vs 인터페이스 | 물려받기(`extends`) vs 기능 약속(`implements`) |
| 배열 vs 리스트 | `length`, 고정 크기 vs `size()`, 가변 크기 |
